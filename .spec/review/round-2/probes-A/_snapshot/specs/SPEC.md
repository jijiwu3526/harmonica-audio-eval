## 1. 项目边界（负责人已定）

**做**：音频比较。给定两段音频（参考演奏 + 用户演奏），输出**客观、可解释的差异指标**。

**只做到数值层。** 自然语言反馈、Agent 生成不在本项目范围内（未来另立项目）。

不做：AI 审美评价、生成理想演奏、**面向终端用户的产品化 UI**、模型训练。

> 仅运行于 Mac、只给开发者看。**这不是**"产品化 UI"——后者指面向口琴学习者的成品界面。
> 理由：先把核心在 Mac 上彻底调试完，再移植手机端。

**平台路线（负责人已裁定，v2.1）**：**Mac 端先行** → 核心调试完毕 → 再移植手机端。
手机端的内存约束因此**不是 v0.1 的阻塞项**，但架构不得做出与手机端不可调和的假设。

## 4. 特征性价比（待负责人确认）

"性价比"定义为：**该特征在真实录音条件下能否被稳定提取**（信噪比/麦克风/距离鲁棒性）× **对演奏质量的区分度** × **(1 / 实现与调参成本)**。

| 特征 | 稳定性 | 区分度 | 成本 | 判断 |
| --- | --- | --- | --- | --- |
| 音高 / 音准（cents） | 高 | 高 | 低 | **核心** |
| 节奏 / 音符起始 | 高 | 高 | 低 | **核心** |
| 力度 / 能量 | 中高 | 中高 | 低 | **核心** |
| 颤音 / 压音 | 中 | 中（口琴特色） | 中 | 二期 |
| 音色（MFCC/谱质心等） | **低**（麦克风/距离/环境敏感） | 中 | 中 | 暂缓，需先做设备归一化 |

结论建议：首期只做 **音高 + 节奏 + 力度** 三维。音色因设备依赖性暂缓。**待负责人批准。**

## 5. 时间对齐：行为契约（不指定算法）

两段同一首曲子的演奏，长度/速度不同，需先建立时间映射。

**本规格承诺的行为**（这些是契约，不可协商）：

1. **产出**：一个单调、近似保序的时间映射 `ref_time → user_time`，以及由它导出的
   `mean_abs_warp_sec`、`tempo_ratio`、`confidence`。
2. **约束**：映射路径必须受**全局带宽约束**，禁止病态弯曲（例如把整首曲子压成一点）。
3. **失败语义**：无法建立有效映射时，**必须显式失败**（`CORE_BUILD_FAILED`），
   **不得**静默降级为"不配准直接逐点比"。
4. **口琴特殊性**：口琴是**单声部**乐器，音高曲线信息量远高于 chroma；
   chroma 会丢失八度信息、无法反映走音。
   → 因此**禁止只依赖 chroma 类的八度不变特征**作为唯一对齐依据。
5. **两轴分离**：时间轴必须同时提供**保留源时间**与**时间归一化**两种表示
   （对应 Core 数据面的 mapped / warped）。**段级节奏指标必须在保留源时间的表示上计算**，
   否则归一化会静默抹掉抢拍拖拍。

> **算法选型不在此处冻结。** 具体用什么特征、什么对齐算法、什么带宽参数，
> 属于 Component Architect（L2）在实现层的选型，见 `COMPONENTS.md`。
> 参考路线（CENS 粗对齐 + f0 细对比）作为**候选实现之一**记录在 `research/`，不具约束力。
>
> 依据：[librosa 音乐同步 tutorial](https://librosa.org/doc/latest/auto_tutorials/03-advanced/plot_music_sync.html)、[Müller 2006 多尺度音频同步](https://audiolabs-erlangen.com/content/05_fau/professor/00_mueller/03_publications/2006_MuellerMattesKurth_MultiscaleAudioSynchronization_ISMIR.pdf)。

**待负责人确认**：§5 行为契约（1–5 条）是否完整覆盖你要的对齐保证。

## 6. 关于"分段"（回答负责人疑问）

分段的用途**不是让你手动切音频**，而是决定**反馈的空间粒度**。

对比分析必然要回答"哪一段有问题"。所以要么：

- **A. 人工分段**：负责人/标注者给定时间点（如 0–8s / 8–16s），最简单可控；
- **B. 固定时长等分**：程序自动每 N 秒切一段，零成本，但切点可能落在音符中间；
- **C. 按乐句/结构自动切**：算法找重复结构或静音间隙切分，最贴近音乐，但实现成本最高；
- **D. 曲谱驱动**：按谱面乐句切，最准，但需要谱面数据。

首期建议 **A + B**（默认等分，允许传入人工切点）。**是否需要 C/D 由负责人决定。**

## 7. 音高提取：行为契约（不指定引擎）

**本规格承诺的行为**（这些是契约，不可协商）：

1. **产出**：逐帧 f0 曲线（Hz）+ 逐帧 voiced/unvoiced 判决 + 置信度，
   时间戳必须与对齐后的时间轴一致。
2. **绝对音高**：必须输出**绝对音高**（可映射到 MIDI 音高号），
   **不得**只输出八度不变的音级（chroma）——否则无法评估走音与八度错误。
3. **精度目标**：在 ≥150 ms 的稳定音符上，中位误差应 ≤ 50 音分。
4. **必须记录采样率**：f0 估计结果**依赖采样率**。已实测：同一段音频在 22.05 kHz 下
   会把 D5 判成 D4（恰好 −1200 音分），44.1 kHz 下正常。
   → 因此采样率是**结果的成因**，必须随结果一起记录，且对齐两侧必须同率。
5. **引擎可替换**：具体引擎（神经网络或传统 DSP）属实现选型；
   但**必须有独立对照组**，用同一批音频量化两者的差异。

> **引擎选型不在此处冻结。** 候选（`torchcrepe` 神经网络 / `librosa.pyin` 传统 DSP）
> 作为实现候选记录在 `COMPONENTS.md`，不具约束力。
> 但 §7.5 要求：最终选定前，必须有一次**对照实验**，用数据决定选型。

**待负责人确认**：§7 行为契约（1–5 条）是否完整覆盖你要的音高保证。

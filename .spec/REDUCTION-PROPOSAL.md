# 减法提案：把注意力从"造检查"收回到"造产品"

> 起因：负责人要求复盘"有没有遗漏、会不会干着干着走偏"。
> 本文是那次复盘的**可执行部分** —— 不是感想，是带证据的取舍清单。
> 每一条都可用命令复核，不接受"我觉得"。

---

## 一、走偏的证据（全部实测，非估算）

### 1.1 投入产出严重失衡

```
契约层 contract.py                     1200 行
插件层 algorithms/*.py（4 文件）        868 行
─────────────────────────────────────────────
模具本体合计                           2068 行

Build Instructions（21 份）           11355 行
tools/ 检查工具（13 个）                5548 行
规格层（COMPONENTS/CONTRACTS/SPEC/PLAN） 1161 行
─────────────────────────────────────────────
规格 + 验证装置合计                   18064 行   ← 8.7 倍于模具本体
```

**更有说服力的一组数字**（`ast` 实测）：

```
空壳函数 79 个 / 有实体实现的函数 14 个
```

**这个项目的目标产物是「口琴双音频对比 → 客观数值指标」。
而现在能跑的只有 14 个函数，算法一个都没实现。**

### 1.2 检查装置已经失控，且没有统一入口

`tools/` 下 13 个脚本，**没有 Makefile、没有 run_all.sh、没有 CI** ——
全部靠人手逐个跑。实测引用数：

| 工具 | 被多少文件引用 |
| --- | --- |
| `verify_shell.py` | 23 |
| `check_counts.py` | 3 |
| `check_plugin_contract.py` | 2 |
| `check_scratch_freshness.py` | 1 |
| `check_deliverable_hygiene.py` | **0** |

**没有入口意味着这些检查随时可能被忘记跑** ——
即"写了 5548 行检查，但没有任何机制保证它们被执行"。

### 1.3 我在用验证装置替代产品

本轮我亲手造出的三个工具，**没有一个在保证产品质量**：

| 工具 | 它在防什么 | 为什么可能该删 |
| --- | --- | --- |
| `check_deliverable_hygiene.py` | 智能体脚手架泄漏进交付物 | 防的是**我的工作方式**问题，不是产品问题 |
| `check_scratch_freshness.py` | 误用 `_scratch` 陈旧副本论证主包 | 同上，且 `_scratch` 本就要被清理 |
| `check_plugin_contract.py` 的 14 组注入 | 我的判据本身写错 | 有价值（它证明插口成立），但 1184 行里 900 行是注入自证 |

**AGENTS.md 铁律 4**：「零噪声。不写『以后可能有用』的抽象层。」
**我加的检查正是这句话的反例** —— 它们防的是"我可能会犯的错"，
不是"产品可能有的缺陷"。

### 1.4 注意力被自己的错误产物吸走（本轮最真实的机制）

`check_counts.py` 的判据**锚在行号**上。文档一重写，**25 条判据同时失配**。
这个脆设计是我自己造的，然后我花了**一整个子代理任务**去修它。

**这才是"干着干着走偏"的真正机制**：不是某一件大事做错，
而是**注意力被自己的错误产物吸走，且吸走的过程看起来像在工作**。

## 二、减法清单（建议，需负责人裁定）

### 第一刀：砍掉只防"我"的检查 —— 预计减 1100–1300 行

| 动作 | 对象 | 理由 |
| --- | --- | --- |
| **删** | `check_deliverable_hygiene.py`（109 行） | 0 处引用；防的是工作方式污染，不是产品缺陷 |
| **删** | `check_scratch_freshness.py`（174 行） | `_scratch` 是过渡工件，算法注入后即失去价值 |
| **瘦身** | `check_plugin_contract.py`：1184 → 约 400 行 | 保留 13 条不变量判定，删掉 14 组注入自证框架与报告排版 |
| **保留** | `verify_shell.py` / `check_counts.py` / `check_bi_scripts.py` 等 | 这些**直接保证空壳与规格的一致性**，是本项目质量的地基 |

**判断标准（请负责人确认）**：
> 一条检查该不该留，问的是「**它能发现产品质量问题吗**」，
> 不是「它能发现我犯的错吗」。

### 第二刀：给剩下的检查一个统一入口 —— 预计 +40 行，减掉"忘了跑"的风险

新建 `tools/check_all.sh`，把该跑的检查串成一个命令，**任一失败即非 0**。
没有入口的检查等于没写。

### 第三刀：冻结 21 份 Build Instructions，不再扩写

理由：现在的精度已经**超过实现阶段的需要**。
算法注入时若发现规格不够，届时改；**现在继续改是在给空壳写说明书**。

**但保留一个例外**：`FILE-301`（Host 装配）因为 GC-204-01 未裁定，
其 §8 判据与 `host/app.py` 签名绑定，裁定后需要同步一次。

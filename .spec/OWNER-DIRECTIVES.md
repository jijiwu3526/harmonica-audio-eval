## 指令 1 · 组件 README：✅ 批准执行

**原话**：「组件README做」

### 具体范围

为每个组件目录补一份 `README.md`：

```
harmonica_eval/core/README.md
harmonica_eval/algorithms/README.md
harmonica_eval/host/README.md
harmonica_eval/cockpit/README.md
```

（若你认为合并为更少文件更合适，可提建议，但**不得少于 4 个组件各自可查**。）

### 硬性要求

1. **是索引，不是权威。**
   每份 README 开头必须有一行醒目声明：
   > **本文是索引，不是权威。** 权威在 `.spec/` 与源码铭牌。
   > 本文任何内容与它们冲突时，**以它们为准**，并把冲突报给负责人。

2. **不新建信息源。** 全部内容从已有材料**搬运 + 指向出处**。
   每个事实性陈述都要给 `文件:行号`。

3. **不得重写规格。** 已在 `.spec/build/` 写清楚的内容，
   README 只做"这个组件要做什么 / 相关文件在哪 / 关键约束是什么"的收敛。

4. **必须标出未决项。** 例如 `GC-204-01`（session_id 矛盾）、
   `GC-204-08`（装配根冲突）—— **标红并写明"未裁定，阻塞 Freeze"**，
   不得假装已经解决。

5. **端口清单不得手抄。**
   `core/README.md` 里的端口表必须是**从 `profile.py` 生成**的，
   并注明"由 `profile.PORTS` 生成，改端口请改 `profile.py`"。
   ★ 手抄的第二份端口表就是下一次陈旧的起点。

## 指令 2 · ★★ 禁止注入实现 ★★

**原话**：「现在没有在造，现在是还要进行审查，审查完后最后再注入。
**在没有同意之前，绝对不允许注入**。」

### 这条约束的精确定义

**禁止**：向任何 `harmonica_eval/` 下的文件写入**实体实现** ——
即让空壳函数从 `raise NotImplementedError("SHELL: ...")` 变成真实逻辑。

包括但不限于：
- 实现任何算法（pitch / timing / dynamics 的计算逻辑）
- 实现 `Registry.register/list/get`
- 实现 `runtime.resolve_inputs/validate_result`
- 实现 `core/` 任何文件的函数体
- 实现 `host/app.py` 的 `build_default_app` 等
- 实现 `cockpit/app.py` 的任何方法

**允许**：
- 写规格、Build Instruction、README、索引
- 写检查工具与测试
- 修改铭牌、docstring、签名、类型注解
- 修改契约层的**类型定义**（不是实现）
- 审查、盲审、交叉审计

### 理由（负责人已明确）

当前阶段是**审查**，不是**注入**。
审查必须在模具**未注入**的状态下进行 ——
一旦注入，审查者看到的就是自己的实现，而不是独立的规格。
**这会破坏盲审的前提。**

### 解除条件

**只有负责人明确说"可以注入了"，本指令才解除。**
在此之前，任何 AI、子代理、工具都不得写入实现。

★ 违反本指令的后果：整轮盲审作废，必须重做。

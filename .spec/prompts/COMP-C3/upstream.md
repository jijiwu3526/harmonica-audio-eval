## ROLE

**Algorithm** —— 消费标准数据面，返回标准算法结果。

## WORKFLOW POSITION

最下游。**只读**数据面，不与任何人协作。
v0.1 只装一个实例；架构必须支持多个并存且结果可比对。

## CAPABILITY

- 从数据面读取自己声明的端口
- 完成一个独立算法能力（v0.1：音准 / 节奏 / 力度）
- 返回标准化结果信封 `AlgorithmResultEnvelopeV1`
- **自报本次实际消费了哪些端口**（`consumed_ports`）

## BOUNDARY（明确不做）

- 不管理音频生命周期；不做对齐
- 不碰 UI / 平台 API
- **不请求 C2 生成新数据**
- 不访问文件系统固定路径；不访问网络
- 不修改任何端口数据

## CRITICAL DECISIONS

| # | 决定 | 理由 |
| --- | --- | --- |
| D1 | **只读** | Seal 后不可变 ⇒ 算法无法污染他人输入 |
| D2 | **`required_ports` 单向** | 仅用于 `exists? YES/NO`；缺失即 `INCOMPATIBLE`，**绝不反推 C2 生成**。这是整套设计的良心所在 |
| D3 | **失败被隔离** | 自身 FAILED 不影响数据面与其他算法 |
| D4 | **失败也返回信封** | 异常不穿透到 C1，便于故障隔离与上报 |
| D5 | **不持有跨会话指针** | 防止数据面生命周期错配 |
| D6 | **结果是绝对值，不是相对评价** | SPEC §1：只做到数值层，不做教学结论 |

## BUDGETS

| 项 | 预算 | 状态 |
| --- | --- | --- |
| 单算法耗时 | **未测** | v0.1 无超时机制（已知缺口） |
| 单算法内存 | **未测** | v0.1 无硬上限（已知缺口） |
| 结果体积 | 需要有上限 | 具体数值待 L2 |

> **诚实声明**：v0.1 若某算法死循环，**会卡住整个 Rack**。
> 超时与内存硬上限明确留待 v0.2。此缺口已写入 `COMPONENTS.md` §7，不隐瞒。

## RISKS

| # | 风险 | 后果 |
| --- | --- | --- |
| R1 | 算法死循环 | 卡住编排；v0.1 无解 |
| R2 | 算法返回 NaN / 非法 schema | 污染结果集 → C1 必须做 schema 校验 |
| R3 | 算法反向要求 C2 生成数据 | 深组件被破坏，数据面变成算法需求的函数 |
| R4 | 算法依赖 process-global 可变单例 | 多算法并存时互相干扰，Invariant A 失效 |
| R5 | 采样率假设硬编码 | 换采样率后静默给出错误音高（八度级错误） |

但其输入接口形态继承自 C2 的 OC1，故 `downstream.md` 需等 OC1 关闭。

# COMP-C2 · upstream.md

> 上行视图 / Decision Compression（宪章 §14.1）
> 面向：L0 负责人 · L1 系统总师
> 这是全系统**唯一的核心组件**，也是当前**风险最集中**的地方。

---

## ROLE

**Audio Core** —— 把两段输入音频编译成一份完整、不可变、与算法无关的分析数据面。

## WORKFLOW POSITION

系统正中央。上游只有 C1（拿输入、报状态）；下游只有 C3（供只读数据）。
**它不知道算法的存在，也不需要知道。**

## CAPABILITY

- 接收两段原始音频并**标准化**（采样率 / 声道 / 数值表示 / 时间原点）
- 建立两段之间的**时间映射**
- 实体化两套对齐表示：保留源时间（mapped）+ 时间归一化（warped）
- 按 `CORE_PROFILE_V0.1` 产出分析数据面
- Seal 后提供**只读、自描述、受控访问**

## BOUNDARY（明确不做）

- 不做 UI；不做教学评分；**不判断吹得好不好**
- 不实现任何具体音高算法
- **不知道有哪些算法被装载；不知道算法是否存在**
- 不持久化 UI 状态
- **不因为某个算法需要某端口就去生成它**（兼容性检查是单向的）

## CRITICAL DECISIONS

| # | 决定 | 理由 |
| --- | --- | --- |
| D1 | **数据面自描述**：外部通过 manifest 枚举端口 | 使 C2 可增删端口而不破坏外部 —— 深组件的关键 |
| D2 | **两份 aligned PCM 永远存在** | 本仓自定保证（★ 原写「宪章 §11 逃生口」是伪造引用；宪章 §11 是 Mission Threads）：算法永远能拿 PCM 自行预处理，故 profile 只决定「快不快」，不决定「能不能」 |
| D3 | **Seal 后不可变** | 使「算法运行期数据面有效」成为天然成立的事实，而非需要协调的约定 |
| D4 | **换算法 Core 零修改** | 依赖方向可自动检查，不靠纪律 |
| D5 | **禁止静默降级** | 对齐失败必须显式失败；**不得**退化成「逐点硬比」 |
| D6 | **端口必须自带 `sample_rate`** | 实测：同一音频 22.05 kHz 下 f0 会被判低八度（−1200 音分）。采样率是**结果的成因**，不是元数据 |
| D7 | **端口必须自带 `timeline_basis`** | 归一化会抹掉抢拍拖拍；拿 warped 轴报节奏错误是构造性错误 |

## BUDGETS

### 已实测（Mac / 3 分钟音频 / 44.1 kHz / mono / float32）

| 项 | 实测值 | 场景 |
| --- | --- | --- |
| 构建耗时 | **0.34 s** | PCM 底座 + 1 档频谱（真实 FFT） |
| 数据面规模 | **95.5 MB** | PCM 底座 ×3 + RMS 包络 + 低分辨率 chroma |
| 数据面规模 | 222 MB | 若**额外预存** 1 档 STFT 幅度谱 |
| 数据面规模 | 477 MB | 若额外预存 3 档频谱 |
| 数据面规模 | 1.49 GB | 若含帧库 + 复数谱 |

估算与实测偏差：**−0.0%**（字节数是纯算术量，可信）。

### 关键实测结论（推翻原设想）

**预存频谱的经济性极差**：一档 2048/512 幅度谱占 127 MB，现算只要 **65 ms**。
3 分钟尺度 ⇒ **每省 1 秒需付 778 MB**。

**由此得到的裁定**：频谱类端口**只冻结定义**（n_fft / hop / window / 单位 / 时间基准），
**不预存字节**，按需实体化 + 缓存。

> **冻结定义 ≠ 预存字节。** 可比性来自「定义唯一」，不来自「字节在场」。
> 这是本组件最重要的设计收敛，同时满足宪章 §9 契约要求与内存约束。

## RISKS

| # | 风险 | 后果 | 缓解 |
| --- | --- | --- | --- |
| R1 | 端口目录被当成 L1 契约 | 深组件被破坏；发明假阻塞项（**v1 已犯，已修正**） | 端口目录属 L2 内部 |
| R2 | 对齐失败时静默退化 | 产出「看似正常但完全错误」的指标 | D5：强制显式失败 |
| R3 | 归一化轴被用于节奏指标 | 抢拍拖拍被抹掉，指标恒为「完美」 | D7：端口声明时间基准 |
| R4 | 采样率未随结果记录 | 复现时 f0 差一个八度 | D6 |
| R5 | 全物化导致内存/磁盘膨胀 | 手机端不可行 | 已实测裁定：定义按需 |
| R6 | **存储/计算形态未定就冻结接口** | 返工面覆盖全部下游组件 | **已发生一次并已撤回**（见 `.spec/draft/`） |

# COMP-C1 · upstream.md

> 上行视图 / Decision Compression（宪章 §14.1）
> 面向：L0 负责人 · L1 系统总师
> 只传递上层真正需要的决策信息；不暴露组件内部实现细节。

---

## ROLE

**Framework / Host** —— 应用宿主与编排者。

## WORKFLOW POSITION

最外层。全系统**唯一**接触平台（文件系统 / 权限 / 麦克风）的组件；
全系统**唯一**知道「存在哪些算法」的组件。是 composition root。

## CAPABILITY

- 应用生命周期；会话创建与销毁
- 接收两段音频资产（参考 + 练习）
- 驱动 C2 构建数据面；**只在 `DATA_READY` 之后**才允许算法启动
- 算法执行编排（决定跑哪些算法实例、按什么顺序）
- 把平台异常与组件内部失败**归一化**为统一错误码
- 向 C4 提供**只读可视化投影**

## BOUNDARY（明确不做）

- 不做 DSP；不做对齐；不解析数据面内部结构
- 不实现算法；不判断算法结果对错
- 不持有 C2 / C3 的任何内部符号（只传不透明句柄）

## CRITICAL DECISIONS

| # | 决定 | 理由 |
| --- | --- | --- |
| D1 | **编排逻辑放 C1，不放 C2** | 若放 C2，「Core 零算法知识」只能靠纪律维持；放 C1 后它成为可**自动检查的结构事实**（`core/` 不许 import `algorithms/`） |
| D2 | **算法注册表放 C1** | 装配点唯一，新增算法不改处理 DAG |
| D3 | **状态单调推进** | 禁止跳过 `DATA_READY` 直接触发算法；这是 Invariant A 的前提 |
| D4 | **错误归一化** | 内部异常不得穿透到 UI；C1 只产出错误码 + 简短 detail |

## BUDGETS

| 项 | 预算 | 依据 |
| --- | --- | --- |
| 内存 | O(1) 业务状态 + 句柄 | 不持有音频或数据面缓冲 |
| 耗时 | 编排本身零 DSP 开销 | 只做状态推进与调度 |
| 参考值 | C2 构建 3 分钟音频 0.34 s | `COMPONENTS.md` §10 实测 |

## RISKS

| # | 风险 | 后果 |
| --- | --- | --- |
| R1 | 编排下沉到 C2 | Core 获得算法知识，Invariant B（换算法 Core 0 修改）失效 |
| R2 | C1 直接读端口内容做展示 | C1 耦合到端口目录，而端口目录属 C2 内部 → 深组件被破坏 |
| R3 | C4 直连 C2/C3 | UI 进入计算热路径，UI 崩溃可能影响数据面 |

无。

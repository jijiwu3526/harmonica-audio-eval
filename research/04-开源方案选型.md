# 音频比对 / 特征提取 · 开源方案选型 v1

> **用途**：为《P5 比对设计表》§2.3「技术层」找出可直接用的 GitHub 成熟方案。
> **检索日期**：2026-09-19 ｜ **方法**：AnySearch 公开检索（15 组查询）
> **筛选口径**：只收**声学路线、不做复音转录**这条路上的东西（与我们 §2.4 的技术路线一致）

---

## 0. 一句话结论

> **我们要的三件事里，两件有成熟方案，一件没有：**
>
> | 要做的 | 开源方案 |
> |---|---|
> | **起音 / 节拍 / 速度 / 停顿** | ✅ 很成熟（madmom、librosa、aubio） |
> | **两条演奏的对齐（DTW）** | ✅ 有 SOTA 参考实现（synctoolbox、matchmaker） |
> | **「同一处被反复练了几遍」的切分与追踪** | ❌ **没有现成方案**——只有"乐曲结构分析"，没有"练习重复检测" |

**最后一行最重要**：竞品图上的 **D2 / D4 全空**，在开源生态里**同样是空的**。
→ 这既是好消息（缝隙真实存在），也是坏消息（**没有免费午餐，得自己建**）。

## 1. 推荐栈（四层，最小可用组合）

| 层 | 选它 | 干什么 | 为什么是它 |
|---|---|---|---|
| **① 特征与起音** | **madmom** ｜ 备选 **librosa** | 起音检测、节拍、速度、下拍 | madmom 专为 MIR 设计，起音/节拍/速度是它的强项；librosa 生态最大、教程最多 |
| **② 两条演奏对齐** | **synctoolbox** | DTW 音乐同步（audio → audio） | 作者是 ISMIR《Music Performance Analysis》综述的作者，有完整同步流水线；备选 `librosa.sequence.dtw` |
| **③ 响度 / 力度** | **pyloudnorm** | LUFS（ITU-R BS.1770-4）响度测量 | 标准实现，可控制门限块与频率加权 |
| **④ 调试验证** | **Sonic Visualiser + Vamp 插件** | 肉眼核对起音/速度/对齐结果 | 图形化，能直接看到算法在哪出错；`sonic-annotator` 可批量跑 |

**移动端补充**：**aubio** 是 C 库，且有 **iOS SDK**（`aubio-ios-sdk`），可考虑端侧预处理（重采样、起音）以减少上传量。

## 2. 分类清单

### 2.1 特征提取基础库

| 库 | 语言 | 能做什么 | 备注 |
|---|---|---|---|
| **librosa** | Python | 音乐/音频分析的"地基"，MIR 系统的标准构件 | 生态最大、教程最多（含 DTW 音乐同步教程）；**速度最慢**——audioFlux 的 benchmark issue 里明确"librosa takes the most time" |
| **audioFlux** | C + Python | 系统性多维特征提取 | 比 librosa / torchaudio 快（长音频上明显）；essentia 也比它慢 |
| **essentia** | C++ / Python | 全面 MIR 分析 | 功能全，但长音频提取比 audioFlux/librosa 慢 |
| **torchaudio / nnAudio** | Python | 张量化音频前端，可上 GPU | 适合大批量离线处理 |

### 2.2 起音 / 节拍 / 速度

| 库 | 能做什么 | 备注 |
|---|---|---|
| **madmom**（CPJKU） | **起音检测、节拍、下拍、拍号、速度估计**，含神经网络实现 | **本项首选**。CPJKU（林茨）出品，与 partitura 同一实验室 |
| **librosa** | 起音、拍点、tempogram | 够用，速度慢 |
| **aubio** | 分段（每个 attack 之前切开）、音高检测、跟拍、实时 → MIDI | **C 库**，有 **iOS SDK**；适合端侧/实时 |
| **all-in-one**（mir-aidj） | 一次给出 **Tempo / Beats / Downbeats / 功能段边界 / 段标签** | 结构分析方向的整合包，对"切段"有用 |

### 2.3 两条演奏的对齐（★ 我们最核心的一步）

| 库 | 能做什么 | 备注 |
|---|---|---|
| **synctoolbox**（meinardmueller） | **基于 DTW 的音乐同步**，高效/鲁棒/高精度；含完整 **audio→audio** 同步流水线 notebook | **本项首选**。有 feature extraction + 高分辨率同步 |
| **matchmaker**（pymatchmaker） | **实时**音乐对齐 / 乐谱跟随；兼容现代 MIR 库 | ISMIR 2025 论文 + 开源；**需要实时流程时用它**（离线用 synctoolbox） |
| **librosa** | `sequence.dtw` + 音乐同步教程 | 入门最快；大规模/高精度不如 synctoolbox |
| **DTW suite**（dynamictimewarping.github.io） | DTW 家族算法的参考实现 | 想自己改算法时读它 |

> ⚠️ 别忘了 §2.3 记的那条失效条件：**速度差大、有反复、有重起 → DTW 会病态对齐**。
> 所以流程必须是 **先切段 → 再段内对齐**，而不是整曲硬对。synctoolbox 的高分辨率同步能缓解，但不能免除切段。

### 2.4 响度 / 力度

| 库 | 能做什么 | 备注 |
|---|---|---|
| **pyloudnorm** | **ITU-R BS.1770-4** 响度（LUFS），可调门限块与频率加权 | 力度轮廓的响度层用它 |
| **loudness**（PyPI） | 同上，底层是 C++ | 更快的备选 |
| librosa | RMS / 分帧能量 | 做**音符级声级序列**够用 |

> ⚠️ 三者都算出"正确的响度"，但**跨次可比性取决于录音豆有没有 AGC**——算法救不了硬件（见 P5 §1.3a）。

### 2.5 声部平衡（我们标的"技术上最难"）

| 库 | 能做什么 | 关键限制 |
|---|---|---|
| **Demucs**（facebookresearch） | SOTA 音乐源分离 | ⚠️ **分离的是 drums / bass / vocals / other——器乐级**，不是"钢琴内部的旋律 vs 伴奏" |
| **Spleeter**（Deezer） | 2/4/5 stems 分离 | 同上，面向流行歌曲编曲 |
| **Open-Unmix**（SiSEC） | 参考实现 | 同上 |
| **bytedance/music_source_separation** | 可自训练的分离框架 | 需要自己造钢琴内声部的数据 |

> **结论：开箱即用的声部平衡方案不存在。** Demucs 那套 stems 与我们的需求不对口——
> 钢琴独奏里"旋律/伴奏"是同一件乐器、同音区、同音色，属于**研究问题**。
> → 这一项应作为**"下一代硬件/算法建议卡"**的内容，不进 24h（与 P5 §2.5 一致）。

### 2.6 自动转写（我们**刻意避开**的路线，列出以备对照）

| 库 | 备注 |
|---|---|
| **bytedance/piano_transcription** | 高分辨率钢琴转写，**含踏板**；论文称踏板起音 F1 **91.86%** |
| **spotify/basic-pitch** | 轻量神经 AMT，支持 pitch bend |
| **Magenta Onsets and Frames** | 钢琴转写经典模型；另有 **magenta-js** 版可在浏览器跑 |
| **MT3** | 多任务转写 |

> 列出来是为了**证明我们绕开它是有理由的**：这些都是"转成音符"的路线，
> 而 P5 §2.4 已论证：**可靠的技术部分恰好就是可比的部分**，转录既不可靠又不可比。

### 2.7 乐谱 / 演奏符号分析

| 库 | 能做什么 | 备注 |
|---|---|---|
| **partitura**（CPJKU） | 处理**符号音乐**：MusicXML / MIDI / **Humdrum kern** / MEI | 与 madmom 同实验室；要做"乐谱 ↔ 演奏"对齐时用它 |
| **MPM-Toolbox**（axelberndt） | Music Performance Markup 的图形编辑与分析 | 偏符号层，备查 |

### 2.8 可视化与批量调试

| 工具 | 能做什么 | 备注 |
|---|---|---|
| **Sonic Visualiser** + **Vamp 插件** | 图形化查看起音、速度、调性等；**可用于多音频的自动时间对齐** | **强烈建议用它验证我们自己的流水线** |
| **sonic-annotator** | 批量跑 Vamp 插件并导出结果 | 批处理/回归测试 |
| **QM Vamp plugins** | 起音、速度、调性等常用插件集 | 与 Sonic Visualiser 配套 |

## 3. ★ 关键缺口：切分与"同处追踪"没有现成方案

我们搜了三个方向，全部落空：

| 搜的方向 | 找到的 | 没找到的 |
|---|---|---|
| 音乐结构分析 | 有：歌曲分段、副歌定位、audio thumbnailing（找最有代表性的一段） | ❌ 没有"练习录音里同一处被反复了多少次" |
| 练习重复检测 | 只有**练习方法学**的论文（blocked vs random practice 等） | ❌ 没有对应的**音频检测**开源实现 |
| 段落边界检测 | 有：all-in-one 的功能段边界 | ❌ 那是"乐曲结构"，不是"练习单元" |

**这个缺口的准确描述**：

> 学术界做的是 **乐曲结构**（这首歌有哪几段）；
> 我们要做的是 **练习结构**（这个人刚才把第 17 小节弹了 6 遍，第 3 遍最好）。
> 两者共享原语（起音、对齐、相似度），但**问题不同，没有现成轮子**。

**这意味着两件事**：
1. **好消息**：P5 里 D2 / D4 的"全空"是真的——**连开源生态都空**，说明这不是我们没找到，是确实少有人做
2. **坏消息**：**F3（自动切分）和 D4（同处轨迹）必须自建**，且没有参考实现可抄——**这是本项目最硬的一段工程量**，也是最有资格叫"创新"的一段

**可行的自建路径**（用现成原语拼）：
```
audio → 起音序列（madmom）
      → 静音/长停顿切段（IOI 阈值）        ← F3 的粗切分
      → 段间相似度（chroma + DTW，synctoolbox）
      → 相似段聚类 → "这是同一处的第 N 遍"   ← D4 的地基
      → 段内对齐 → 差异量                   ← D2 的输入
```

## 4. 坑与待核实

| # | 事项 | 说明 |
|---|---|---|
| 1 | **许可证未核实** | 本表**没有**标注各库许可证。商用/参赛作品必须逐个核实（尤其 Demucs、Spleeter、piano_transcription 这类模型权重） |
| 2 | **madmom 的安装门槛** | 历史上的版本对 Python / NumPy 版本较敏感，环境需预留调试时间 |
| 3 | **librosa 的性能** | audioFlux 的 benchmark 明确 librosa 最慢；离线批处理要考虑（或用 audioFlux） |
| 4 | **Demucs 不能解声部平衡** | 见 §2.5，它是器乐级分离，与钢琴内声部不对口 |
| 5 | **DTW 病态对齐** | 见 §2.3 与 P5 §2.3；必须先切段 |
| 6 | **端侧 vs 云端** | AWS 侧用 Python 栈最顺；若需端侧，aubio（C + iOS SDK）是唯一现成的移动友好选项 |
| 7 | **实时性** | 现场 Demo 若要"边练边出结果"，需 matchmaker 这类实时对齐；纯离线用 synctoolbox 更稳 |

## 5. 与 P5 §2.3 技术层的对应

| P5 §2.3 要测什么 | 本表对应的方案 | 成熟度 |
|---|---|---|
| 起音检测（onset） | **madmom** / librosa / aubio | ⭐⭐⭐ 成熟 |
| 停顿与 IOI | 自建（起音序列差分）——原语现成 | ⭐⭐⭐ |
| 速度曲线 | **madmom** tempo/beat + 起音序列 | ⭐⭐⭐ |
| **演奏对齐** | **synctoolbox**（离线）/ **matchmaker**（实时） | ⭐⭐⭐ 有 SOTA 参考实现 |
| 响度 / 力度 | **pyloudnorm** / librosa RMS | ⭐⭐⭐ |
| 力度轮廓对比 | 自建（归一化 + 相关/DTW）——原语现成 | ⭐⭐ |
| **声部平衡** | ❌ **无对口方案**（Demucs 不对口） | ⭐ 研究问题 |
| 音符转录（避开） | basic-pitch / piano_transcription / MT3 | ⭐⭐⭐ 但**我们不走** |
| 音色（不可比） | 频谱特征，任何库都能算 | 算得出但**不该报** |
| 录音可用性（置信度门限） | 自建（RT60 / 直混比 / SNR） | ⭐⭐ |
| **切分与同处追踪** | ❌ **无现成方案，必须自建** | ⭐ 缺口 |

## 依赖方向（这是本图最重要的部分）

**这些不是画上去的箭头，是 `tools/verify_shell.py` 里逐条强制检查的。**

| 文件 / 目录 | 禁止知道 | 含义 |
|---|---|---|
| `core/` | algorithms、host、cockpit | 核心不认识算法的存在 |
| `algorithms/` | core、host、cockpit | 算法不认识实现细节 |
| `cockpit/` | core、algorithms、host | 界面不认识任何内核 |
| `contract.py` | core、host、algorithms、cockpit | 契约不认识任何实现 |
| `profile.py` | core、host、algorithms、cockpit | 配置不认识任何实现 |
| `__main__.py` | cockpit | 无头入口与界面零依赖 |
| `serve_ui.py` | core、algorithms | 装配点不得绕过深接口 |

### 唯一允许的跨层：`serve_ui.py`

```
C1（host）不 import C4（cockpit）    ← 双向都禁
C4（cockpit）不 import C1（host）
★ 所以「构造 port 交给界面」这一步在既有两层都无处安放
★ 而它不能是 __main__.py —— 上面那张表禁止 __main__ 碰 cockpit
★ → serve_ui.py 是全系统唯一的跨层出口
★ → 且它也不属于 C1/C2/C3/C4 任何一层
```

### 界面可以被整体删掉

## 数据流：12 个端口

`profile.py` 冻结 12 个端口，分 6 类。界面把这 12 个全部画出来。

| 端口前缀 | 数量 | 含义 | 采样率 |
|---|---:|---|---|
| `pcm.mapped.*` / `pcm.warped.practice` | 3 | 对齐后的波形 | 绑定 44100 |
| `pitch.*` | 2 | 逐帧基频 | 绑定 44100 |
| `rms.*` | 2 | 逐帧能量 | 绑定 44100 |
| `chroma.lowres.*` | 2 | 低分辨率音级 | **与采样率无关** |
| `notes.*` | 2 | 按音索引表（`notes.reference` 34 音 / `notes.practice` 35 音） | **与采样率无关** |
| `warp_path` | 1 | 时间轴变形路径 | **与采样率无关** |

**两侧音数不等是正常的**（34 / 35），配对由算法处理，不做截断。

## 为什么这套结构撑得住跨端

**目标平台不是 Mac**——Mac 只是开发验证环境。实际目标是 Android 与 iOS。

```
核心依据：contract.py 只依赖 __future__ / dataclasses / enum / numpy / types / typing
★ 零平台依赖，★ 这一点已实测成立
★ 端口是【纯数据 + 运行时事实】，不含任何平台调用
★ Android 用 Kotlin 数组、iOS 用 Swift Array，都能 1:1 实现
```

**端口为什么能跨端**：

```
纯数据        numpy 数组，shape + dtype 明确声明
              ★ 无函数指针、无回调、无平台句柄
时间轴显式    每个端口声明 timeline_basis（参考轴 / 练习轴）
              ★ 杜绝「拿错轴算出恒为 0 的错误结果」
              ★ ★ 而「时间轴错了会静默出 0」是本项目真的踩过的坑
运行时事实分离 shape 只能由数据面生成时给出，不允许从配置反推
              ★ 配置是静态的，形状是运行时的
全集          12 个端口就是全集
              ★ 算法层只能看到这些，看不到音频文件，也看不到其他算法
```

### 端口类型表

| 层 | 端口 | 形状 | dtype |
|---|---|---|---|
| 音频原始 | `pcm.mapped.reference` | `(sample,)` | float32 |
| | `pcm.mapped.practice` | `(sample,)` | float32 |
| | `pcm.warped.practice` | `(sample,)` | float32 |
| | `warp_path` | `(warp_point, axis)` | int32 |
| 特征 | `pitch.*` | `(frame, field)` | f0 / voiced / confidence |
| | `rms.*` | `(frame,)` | 能量轨迹 |
| | `chroma.lowres.*` | `(frame, bin=12)` | 12 音级 |
| | `notes.*` | `(note, field)` | 起音 / 频率 / 能量 |

### 数据面只暴露三个成员

```
数据面内部有 5 个模块、28 个函数，★ 但对算法层只暴露三个成员：

  manifest()    返回 12 个端口的声明清单（形状、dtype、时间轴、元素类型）
                纯查表，零成本
  read(port_id) 按端口名取出实际数据
                纯查表，零成本
  resolution    解析状态：哪些端口可用、哪些缺失、哪些不兼容
                只读属性，零操作

★ 它解决的核心问题：算法无法感知「数据面怎么算出来的」
★ 将来把 DTW 换成别的对齐方法、把自相关换成 YIN，算法一行都不用改
★★ 窄接口 = 降低信息熵 ——★ 那是负责人定的组件设计核心要点在本架构上的落点
```

### 插件与编排的权限隔离

```
同一个解析结果，两层看到的东西不同：

  编排层（C1）  能看到 InputResolution 完整对象
                ★ 可用于判断「该不该降级」
  算法层（C3）  只看到该看的
                ★ 算法无法感知其他算法的状态

★ 这是防止插件误判降级的关键
★ 若算法能看到完整 resolution，★ 它会以为「别的插件不支持这个端口」
★ ★ ★ 于是自己降级 ——★ 而真相是别的插件不支持，与它无关
```

## 关于本图的性质

**这是契约可视图，不是产品界面。**

本项目做的是「双音频对比 → 客观数值指标」，没有自然语言评价、没有界面产品化。
`cockpit` 是给开发者看的投影：它把契约声明的端口与运行时真实的值同时显示出来，
好让「声明」与「实际」对不对得上能一眼看出。

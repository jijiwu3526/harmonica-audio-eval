# 手机端练习流程评估

> 判断依据：只读本仓库代码 + 查公开浏览器兼容性资料。**未做任何兼容性测试。**
> 文中若写「实测」，指的是**在本机 Mac 上跑 `soundfile` / `ffmpeg` 的能力探测**，
> **不是**在手机上跑。手机上的行为**一律标为「需真机确认」**。

---

## §0 结论前置

### **B —— 只能部分成立。流程本身能成立，但有两个必须改的点。**

| 环节 | 结论 |
| --- | --- |
| 选原曲 | ✅ 能成立 |
| 麦克风录制 | ⚠️ API 支持齐，但**录出来的格式读不了**（见 §3） |
| 选本地已有音频 | ⚠️ iOS Safari 行为特殊，需确认 |
| 上传 | ❌ 传文件不行，**必须传 PCM 数组**（见 §3） |
| 对比计算 | ✅ 核心层可移植（继承 `docs/手机可移植性评估.md` 的 A 类结论） |
| 出图 | ✅ 手写 SVG，无外部依赖 |

**两个必须改的点：**

1. **不能把浏览器录的音频文件直接给 `ingest`**（webm/m4a 都读不了）
2. **必须在浏览器端解码成 PCM 再传**（`decodeAudioData` → Float32Array）

## §1 四个 API 的支持情况

数据来源：[caniuse MediaRecorder API](https://caniuse.com/mdn-api_mediarecorder)、
[caniuse MediaRecorder.mimeType](https://caniuse.com/mdn-api_mediarecorder_mimetype)（2026-08 使用率快照）。

| API | iOS Safari | Android Chrome | 备注 |
| --- | --- | --- | --- |
| `MediaRecorder` | ✅ 14 起（14.1+ 桌面 / 14+ iOS） | ✅ | **iOS 13.7 及以下不支持** |
| `MediaRecorder.mimeType` | ✅ 14.1+ | ✅ 49+（47–48 为部分支持） | Chrome 47–48 只能给默认类型 |
| `getUserMedia` | ✅ | ✅ | 需 HTTPS 或 localhost |
| `<input type="file" accept="audio/*">` | ⚠️ 见 §2 | ✅ | iOS 行为特殊 |
| `fetch` + `FormData` | ✅ | ✅ | 但**不可用于本项目**，见 §3 |

**iOS Safari 的版本门槛是最硬的约束**：MediaRecorder 在 iOS 14 之前完全不存在。
若目标用户包含 iOS 13 及更早设备，「手机端录制」这一步不成立。

**麦克风权限的前提**：`getUserMedia` 在非 HTTPS 源下被浏览器拒绝。
本项目 `serve_ui` 用 `0.0.0.0` + 局域网 IP 访问（`http://192.168.x.x:8723/`），
**这在手机上不是安全上下文** —— 这是「手机端录制」的第一道墙，见 §5。

## §2 音频格式：这是真正的卡点

### 2.1 浏览器录出来的是什么格式

| 浏览器 | 默认 mimeType | 容器 | 内层编码 |
| --- | --- | --- | --- |
| Chrome（桌面/Android） | `audio/webm` | **WebM** | Opus |
| Safari / iOS Safari | `audio/mp4` | **MP4/M4A** | AAC |

（具体默认 mimeType 随浏览器版本变化，可用 `MediaRecorder.isTypeSupported()` 在运行时探测。）

### 2.2 本机探测：这些格式 `ingest` 读不读得了

**方法**（不是兼容性测试，是本机能力探测）：
用 `ffmpeg` 生成各浏览器典型输出格式，再交给仓库实际使用的
`soundfile.SoundFile` 打开 —— 走的是 `core/ingest.py:89` 同一条路径。

```bash
$ soundfile 0.13.1 · libsndfile 1.2.2
  可用格式: AIFF AU AVR CAF FLAC HTK IRCAM MAT4 MAT5 MP3 MPC2K
            NIST OGG PAF PVF RAW RF64 SD2 SDS SVX VOC W64 WAV WAVEX WVE XI
```

| 格式 | 代表浏览器 | `soundfile` 能否读 |
| --- | --- | --- |
| **WebM/Opus** | Chrome / Android | ✗ `LibsndfileError` |
| **MP4/M4A/AAC** | Safari / iOS | ✗ `LibsndfileError` |
| CAF | Safari 可选 | ✅ |
| WAV | —— | ✅ |
| FLAC / OGG / MP3 | —— | ✅ |

**结论：`libsndfile 1.2.2` 不支持 WebM 容器，也不支持 MP4 容器。**
（MP4 容器支持在 libsndfile 1.1.0 曾引入，本机 1.2.2 的 `available_formats()`
实测中**不含** `MPEG` 键，故此处按「读不了」处理 —— 见 §6 的复核建议。）

**这意味着：把手机录的音频原样上传，流程在第一步就断。**

## §3 正确路径：浏览器端解码 → 传 PCM

### 3.1 方案

```
浏览器录音（可能是 webm/m4a）
  → MediaRecorder 拿到 Blob
  → AudioContext.decodeAudioData(blob)  ← 浏览器原生 API
  → Float32Array（-1.0 ~ 1.0，浏览器已下混单声道）
  → 传 PCM 字节（不是文件）
  → 服务端 numpy.frombuffer(...) → np.ndarray
```

**实测这条路的每一步都成立**：

```
PCM 3秒 mono 44.1kHz float32 = 529200 字节
→ np.frombuffer(pcm, dtype='float32') → ndarray
→ soundfile 落盘为 WAV → 读回 sr=44100 frames=132000  ✓
```

**关键收益：不需要 ffmpeg，不需要任何新的 Python 依赖。**
`np.frombuffer` 是 numpy 既有能力，落在 `core/ingest.py` 已依赖 numpy 的范围内
—— **不违反零依赖铁律**（AGENTS.md 铁律 2 禁止的是外部库/框架，不是标准库与既有依赖）。

### 3.2 传输量级

| 时长 | PCM (float32 mono 44.1k) | base64 后 |
| --- | --- | --- |
| 45 s（规格下限） | 7.6 MB | 10.1 MB |
| 60 s | 10.1 MB | 13.5 MB |
| 120 s（规格上限） | 20.2 MB | 26.9 MB |

**这是本方案的主要代价**：60 秒练习约 10 MB PCM。
局域网 HTTP 传输可接受；**若要走公网，需分块或改传 WAV（16-bit 可减半）**。

### 3.3 采样率不匹配（易被忽略的坑）

浏览器 `AudioContext` 的采样率由**设备**决定，常见 44.1k 或 48k，
**不保证是 44.1 kHz**。而本项目 `profile.AUDIO.sample_rate` 冻结为 44100。

好在本项目已有重采样通路（`core/ingest.py:53` 导入 `resample_poly`），
所以这不是死路 —— **但必须由上传端带采样率元数据，或服务端接受任意源采样率再重采样**。
**这一点需要在实现时明确，不能假设浏览器会给 44100。**

## §4 现有代码能复用多少

```bash
$ grep -nE "MediaRecorder|getUserMedia|type=\"file\"|FormData" harmonica_eval/cockpit/app.py
（无输出）
```

**当前界面没有任何录音/上传相关实现。** 页面上的路径输入是
`<input id="path-input" type="text" inputmode="url">`（要求手打完整路径），
无 `<input type="file">`，无音频列表。

### 可复用 / 需替换

| 现有件 | 能否直接用于手机 | 说明 |
| --- | --- | --- |

## §5 流程逐环节的可行性

```
选原曲           ✅  仓库已有 6 个 wav，列表点选即可
开始吹（麦克风）  ⚠️  两道墙：
                  ① 非安全上下文（局域网 http://）→ getUserMedia 被拒
                  ② iOS 14 以下无 MediaRecorder
录完落盘         ✅  decodeAudioData → PCM → POST → numpy → data/out/
对比计算         ✅  核心层可移植
出图             ✅  手写 SVG，无外部依赖
```

### 墙 ①：局域网 HTTP 下拿不到麦克风权限（★ 最该先解决的 ★）

`getUserMedia` 要求安全上下文。本项目 `serve_ui` 监听 `0.0.0.0`，
手机上通过 `http://192.168.x.x:8723/` 访问 —— **这不是安全上下文**。

**三条出路**（不是本次评估的结论，只是列出）：
- 自签证书 + HTTPS（手机上要手动信任）
- 一次录好音频，之后用「选文件」代替麦克风
- 局域网内先用「选文件」把流程跑通，麦克风留到有 HTTPS 时

**但注意**：即使走墙 ② 的「选文件」，iOS Safari 的
`<input type="file" accept="audio/*">` 会弹出「照片/拍照/浏览」的选择器
（iOS 不允许直接浏览任意文件夹），**且选到的文件常为 m4a** ——
**所以 §3 的 PCM 路线对「选文件」同样必需，不是只针对麦克风。**

### 性能量级（供估算，非测试结论）

45–120 秒音频在手机上的处理时间**无法在不实测的情况下给出**。
参考量级：桌面端五个样本端到端各约 15–20 秒（含建会话与全部算法）。
手机 CPU 慢于桌面，**但录完只需跑一次**。

## §6 最小可行路径

**问「先在哪跑」比问「手机能不能跑」更有用。** 分三阶段：

### 阶段 1（桌面即可，零风险）：列表点选 + PCM 上传
```
· 界面列出仓库已有 6 个 wav（服务端给路径映射，浏览器拿不到文件系统）
· 用户点一个当「参考」，点一个当「练习」—— 你说的「用模拟吹奏音频代替」
· 现有 6 个按钮的调试流程由此变成真实流程
★ 不需要麦克风，不需要 HTTPS，不碰任何格式问题
★ ★ 这一步做完，「平台能独立测插件」已经成立
```

### 阶段 2（桌面 + 手机局域网）：本地文件选择
```
· 加 <input type="file">，选到 m4a/webm
· 浏览器端 decodeAudioData → PCM → POST
★ 格式问题在浏览器端解掉，Python 侧零新增依赖
★ 手机上不碰麦克风，绕开安全上下文那道墙
```

### 阶段 3（需 HTTPS）：麦克风实时录制
```
· getUserMedia + MediaRecorder
· 需要自签证书或部署 HTTPS
· iOS 14 以下不适用
★ ★ 这一步是唯一「需要手机真机」的，★ 而前两步不需要
```

**结论：手机流程的绝大部分（阶段 1、2）在桌面上就能做完并验证，
只有「麦克风实时录制」这一段需要真机 + HTTPS。**

## §7 哪些是查到的，哪些需真机确认

### 有依据（本机能力探测 + 公开兼容性数据）
- `libsndfile 1.2.2` 读不了 WebM/MP4（§2.2，附实际错误类型）
- `np.frombuffer` 路线成立（§3.1，附实际读回结果）
- MediaRecorder / mimeType 的浏览器支持矩阵（§1，附 caniuse 链接）
- 传输量级（§3.2，纯算术）
- 现有代码零录音/上传实现（§4，附 grep 输出）

### 需真机确认（本评估**无法**给出答案）
1. 目标 iOS 设备的系统版本是否 ≥ 14（低于 14 无 MediaRecorder）
2. `getUserMedia` 在具体局域网/证书配置下是否弹权限
3. 浏览器 `AudioContext` 实际给出的采样率（44.1k？48k？）
4. 45–120 秒音频在目标手机上的实际处理耗时
5. iOS Safari 选文件返回的具体格式（m4a / caf / 其他）

### 需复核我的一处判断
§2.2 里 libsndfile 1.2.2 对 MP4 容器的支持我按「读不了」处理，依据是
`available_formats()` 无 `MPEG` 键。libsndfile 官方文档对 MP4 的支持有
版本差异，**建议在实现前用真机的真实 m4a 文件再确认一次**。

## §8 给实现者的边界

```
✅ 可以做
   · 服务端加一条「从 PCM 字节构造 samples」的入口（不走文件）
   · 界面加音频列表（路径由服务端给）
   · 界面加 <input type="file"> + 浏览器端 decodeAudioData
   · PCM 落 data/out/ 以便复现（AGENTS.md：产出落 data/out/）

❌ 不可以做
   · 引入 ffmpeg 作为 Python 侧依赖（零依赖铁律）
   · 让 soundfile 去读 webm/m4a（实测读不了）
   · 假设浏览器 AudioContext 给 44100
   · 在非安全上下文里指望 getUserMedia 能用
   · 改动 contract.py 的字段（FILE-003:254 冻结）
```

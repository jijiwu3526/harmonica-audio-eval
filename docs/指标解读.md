# 指标解读

> 每个数字是什么、怎么算的、单位是什么、阈值从哪来。
>
> **本文所有数值均由本地实跑产出，非转述。** 复现命令见文末。
> 查不到依据的地方写「未查实」，不编造。

---

## 一、怎么读这张指标表

`metrics.json` 每次运行覆盖，**只反映最后一次对比**。要横向比较多个样本，需分别运行并存档。

| 字段 | 含义 |
|---|---|
| `state` | 会话状态。`DATA_READY` = 数据面就绪 |
| `scalars` | 标量汇总指标（16 条） |
| `series` | 逐条曲线（2 条），含 `t` 与 `values` |

**★ 最重要的一条：`scalars` 里的数字是汇总值，会掩盖个体。**
只看汇总就下结论，是本项目最容易犯的错。三个陷阱见第四节。

## 二、16 个 scalars 逐条解读

### 音准（pitch）

| 指标 | 它是什么 | 怎么算的 | 单位 | 阈值从哪来 |
|---|---|---|---|---|
| `pitch.median_abs_cents` | 逐音绝对音分偏差的**中位数** | `abs(1200·log₂(f0_practice/f0_reference))` 取中位数<br>`pitch.py:134` `hz_to_cents` · `:266` `summarize_deviations` | cents | **无阈值**，纯描述量 |
| `pitch.off_pitch_ratio` | 偏差**超过 50 cents** 的音占已配对音的比例 | `sum(1 for v in abs_values if v > 50.0) / n_notes_used`<br>`pitch.py:313` | ratio ∈ [0,1] | `MAX_CENTS_DEVIATION = 50.0`（`pitch.py:68`）<br>**依据 SPEC.md:191**「≥150 ms 的稳定音符上，中位误差应 ≤ 50 音分」 |
| `pitch.n_notes_used` | 参与计算的音数 | 配对成功且通过时长筛选的音计数 | count | 短于 150 ms 的音被丢弃（`MIN_STABLE_NOTE_SEC`，`pitch.py:75`） |
| `pitch.n_unpaired` | 未能配对的音数（两侧之差） | `abs(len(ref_spans) - len(prac_spans))`<br>`pitch.py:238` | count | **无阈值**，纯描述量 |
| `pitch.sample_rate` | 音频采样率 | 全局音频规格常量 | hz | `profile.AUDIO.sample_rate = 44100`（规格冻结） |

**★ 分母提醒**：`off_pitch_ratio` 的分母是 `n_notes_used`，**两个必须一起读**（`pitch.py:284` 明确注明）。若 `n_notes_used` 很小而 ratio 很高，比率会显得夸张。

### 节奏（timing）

| 指标 | 它是什么 | 怎么算的 | 单位 | 阈值从哪来 |
|---|---|---|---|---|
| `timing.median_onset_sec` | 逐音起音偏差的**中位数**（带符号） | 练习起音时刻减参考起音时刻，取中位数<br>`timing.py:305` `summarize_deviations` | seconds | **无阈值**，纯描述量 |
| `timing.spread_sec` | 起音偏差的**离散度**（MAD） | `median(abs(d - median(d)))`<br>`timing.py` 同函数 | seconds | **无阈值**，纯描述量 |
| `timing.early_ratio` | 偏**早**的音占比 | 偏差 < `-ONSET_DEADBAND_SEC` 的计数 / n_notes_used | ratio | `ONSET_DEADBAND_SEC = 0.023`（`timing.py:121`） |
| `timing.late_ratio` | 偏**晚**的音占比 | 偏差 > `+ONSET_DEADBAND_SEC` 的计数 / n_notes_used | ratio | 同上（闭区间内算 on_time） |
| `timing.on_time_ratio` | **准时**的音占比 | `\|偏差\| ≤ 0.023` 的计数 / n_notes_used | ratio | 同上 |
| `timing.n_notes_used` | 参与计算的音数 | 配对成功且落在死区内判定的音计数 | count | — |
| `timing.n_unpaired` | 未能配对的音数 | `int(n_unpaired or 0)`<br>`timing.py:352` | count | — |

**★ 三个 ratio 恒满足 `early + late + on_time = 1.0`**（实测 0.500+0.179+0.321=1.000）。

**★ 死区 0.023 秒的来历**：对应 23 ms 的人类节奏感知门限——人耳难以察觉比这更小的起音偏移。**代码里只写了这个常量与说明，规格中未见更详细的推导链，故「阈值依据」仅到感知门限这一层。**

### 力度（dynamics）

| 指标 | 它是什么 | 怎么算的 | 单位 | 阈值从哪来 |
|---|---|---|---|---|
| `dynamics.median_db` | 逐音能量差的**中位数** | `20·log₁₀(rms_practice/rms_reference)`，取中位数<br>`dynamics.py:140` `to_db` · `:318` | dB | **无阈值**，纯描述量 |
| `dynamics.spread_db` | 能量差的**离散度**（MAD） | `median(abs(d - median(d)))`<br>`dynamics.py:319` | dB | **无阈值**，纯描述量 |
| `dynamics.n_notes_used` | 参与计算的音数 | 配对成功且通过时长筛选的音计数 | count | — |
| `dynamics.n_unpaired` | 未能配对的音数 | `(n_ref - len(pairs)) + (n_prac - len(pairs))`<br>`dynamics.py:273` | count | — |

**★ dB 值的下限保护**：`DB_FLOOR = -80.0` dB（`dynamics.py:129`）。低于此值的能量被夹住，避免取对数时数值爆炸。代码注明 −80 dBFS 约等于 1e-4 线性幅度，与静音判定门限同量级。

## 三、2 个 series 逐条解读

| 指标 | 它是什么 | 怎么算的 | 单位 | 阈值 |
|---|---|---|---|---|
| `pitch.per_note_cents` | **逐音**带符号音分偏差，第 i 个值对应第 i 对配对音 | 逐音计算后原样落盘<br>`pitch.py:134` | cents | 无 |
| `timing.per_note_onset_sec` | **逐音**带符号起音偏差 | 同上 | seconds | 无 |

两条曲线的 `t` 数组是时间轴（秒），与 `values` 等长。

**★ `timeline_basis` 字段必须核对**，见陷阱 3。

## 四、三个「怎么读」的陷阱

### 陷阱 1：中位数会掩盖离群音

**实测证据**（`01_奇异恩典` 目录）：

```
04_错音    n=34  median=300.0
           零值 10 个，非零 24 个
           逐音值：600, 500, 500, 200, -500, -500, -400, 300, -200, -300,
                    -600, 300, 200, 700, -400, 100, 700, 500, 200, -500,
                    -690, -400, 190, 400
           ★★ 10 个音完全正确（0 音分），24 个偏 190~700
```

```
05_漏音断句  n=21  median=400.0
           逐音值：0, 0, 95, 305, -400, 0, 500, 1200, 1200, 400, 700,
                    0, 400, -400, -500, -1200, -700, -500, 0, -700, -400
           ★★ 其中 3 个是 ±1200（整整一个八度）
```

**★ 只看 `median_abs_cents=300`，无法判断是「34 个音都偏 300」还是「10 个准、24 个偏很多」。**
后者才是错音的典型形态。

**★ 读法建议**：
```
· median_abs_cents 告诉你「整体偏多少」
· off_pitch_ratio 告诉你「有多少比例偏出 50 cents 门限」
· ★ per_note_cents 告诉你「哪些音偏、偏成什么样」
★ 三者一起看，缺一不可
```

**★ `per_note_cents` 落在 `series` 字段而不是 `scalars`**——因为它是序列不是单值。这是契约冻结的划分，不是遗漏。

### 陷阱 2：±1200 是有意设计，不是 bug

**规格依据**（`.spec/build/FILE-201-v1.md`）：

```
:101  基准 f0_hz == ref_hz → 0.0；f0_hz == 2*ref_hz → +1200.0（一个八度）
:108  返回音分，可能任意大（不截断：偏两个八度就是 ±2400，那是真实信息）
:113  chroma 是八度不变的 —— 用它做音准会把「低了一个八度」判成完全正确
:455  不做 chroma / 音级 / 调性分析 —— chroma 会把八度错误藏起来
```

**★ 所以：**
```
· 看到 ±1200 = 该音高了或低了整整一个八度，这是【真实且重要】的信息
· 系统【故意】不做音级折叠，正是为了让它可见
· ★ 若你把 ±1200 归一化成 0，八度错误就被藏起来了
```

### 陷阱 3：时间轴错了会静默出 0

**★ 用 WARPED 轴（时间轴已被 DTW 拉伸对齐）算节奏，结果会恒等于 0**——
因为对齐的定义就是让两条轴逐帧重合，偏差必然为零。

**而且不报错、看起来一切正常。** 这是本项目最隐蔽的陷阱。

**防护与核对方法**：
```
· pitch 与 timing 的输出都声明 timeline_basis=REFERENCE
· ★ 读 metrics.json 时核对 series 里的 timeline_basis 字段
· 预期值：pitch.per_note_cents 与 timing.per_note_onset_sec 均应
  timeline_basis = "REFERENCE"
· ★ 若看到 WARPED → 那是错误数据，不是「更准的对比」
```

**实测确认**：全部 6 次运行（含参考对参考自比）两条曲线的 `timeline_basis` 均为 `REFERENCE`。

## 六、复现方式

### 环境

```
Python  3.13.13
numpy   2.4.4
scipy   1.17.1
soundfile 0.13.1
平台    macOS arm64
```

### 输入音频规格

```
44100 Hz · mono · float32 · 45–120 秒 · peak −3 dBFS
```

**本表实际使用的输入**：
```
参考   harmonica_mvp_dataset/01_奇异恩典/标准旋律版.wav   (3210572 样本 / 72.80 s)
练习   harmonica_mvp_dataset/01_奇异恩典/练习曲/{01..05}.wav
基线   参考对参考（自比）
```

### 命令

```bash
cd <仓库根>          # git clone 下来的目录；下列命令都从仓库根执行
PYTHONDONTWRITEBYTECODE=1 python3 -m harmonica_eval \
  --reference harmonica_mvp_dataset/01_奇异恩典/标准旋律版.wav \
  --practice  harmonica_mvp_dataset/01_奇异恩典/练习曲/01_音准走调.wav
# 产物落在 data/out/metrics.json（缺省）
# 用 --out 可指定到别处
```

### 随机种子

**★ 本流程不涉及随机性。** 音频处理链路（重采样、STFT、DTW、自相关）全部是确定性数值运算，
不含随机采样或随机初始化。同样的输入必然得到同样的输出——六次运行的 `sample_rate`
与各计数指标完全一致，可作旁证。

**退出码**：`0` = 成功且产出指标；`1` = 失败（stderr 会打印 `error_code` 与 `error_detail`）。

| 项 | 状态 |

## 八、总结：三条读法原则

```
1. 汇总值不能代替逐音值
   ★ median 会掩盖离群音。per_note_cents 是判断「系统偏移」与「个别错音」
     的唯一依据。

2. 核对时间轴
   ★ 任何 series 都要看 timeline_basis 字段。
     WARPED 轴算出的 0 是假的 0。

3. 用自比基线区分「真实差异」与「算法噪声」
   ★ 参考对参考时所有指标应为 0。若不为 0，那是算法引入的偏差。
```

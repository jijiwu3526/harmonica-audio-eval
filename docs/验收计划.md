## 1. 插件插拔

### 1.0 「插拔」的定义（★ 先定义，再验收）

★ **定义取自 `.spec/GATE-CHALLENGES-C3.md` GC-204-08 已关闭裁定原文**：

> 负责人裁定 **BLOCK-1 = 方案甲（独立装配根）**。「知道所有实现」这一职责
> 从 C1 移到一个专属位置：bootstrap 独占具体算法的 import，Host 只接收
> 已构造好的 `Registry`。这样要求甲对 Host 继续成立（它确实不 import 具体
> 算法），而「谁负责装配」变成一个**可审查的、单点的物理事实**。

★ **由此推出本项目的「插拔」含义**：

| 维度 | 本项目是否要求 | 依据 |
|---|---|---|
| 动态接入 bootstrap 未知的插件 | ✅ 要求 | 「Host 只接收已构造好的 Registry」⇒ Registry 是运行期对象 |
| **不修改 `bootstrap.py` 一行源码** | ✅ 要求 | 装配知识收敛到单点；改它就破坏了「单点」 |
| 热拔卸（`unregister`） | ❌ **不要求** | 裁定全文未提；Registry 公开面只有 `register/list/get` |

★ **所以「插拔」= 可插 + 不改源码。**「拔」的等价形态是**不注册**——
系统对「插件缺席」有明确行为（见 1.4 红端③）。
